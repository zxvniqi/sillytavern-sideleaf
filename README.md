# 별지 · Sideleaf

QR 결과나 별도로 보관할 메시지만 골라 현재 대화에서 빼두는 SillyTavern 확장입니다.

## 설치

SillyTavern **확장 → Install extension**에 다음 주소를 입력하세요.

```
https://github.com/zxvniqi/sillytavern-sideleaf
```

설치 후 새로고침하세요. SillyTavern 1.19.0 이상을 대상으로 합니다. 별도 서버 플러그인과 빌드 과정은 필요하지 않습니다.

## 사용

1. 저장된 캐릭터 채팅 또는 그룹 채팅을 엽니다.
2. 입력창 옆 **마법봉 → 별지**를 누릅니다. `/sideleaf`로도 열 수 있습니다.
3. **메시지 선택**에서 필요한 메시지만 체크하고 **보관**을 누릅니다.
4. **보관함**에서는 메시지를 하나씩 펼쳐 읽습니다. 다른 채팅의 보관본은 섞이지 않습니다.
5. 선택한 보관본을 **복원**하면 해당 채팅의 **끝**에 추가됩니다. 이후 수정된 대화의 원래 위치를 임의로 추정하지 않습니다.

본문·이름 검색, 페이지 이동, 선택 보관·복원에 집중했습니다. 자동 보관이나 일괄 삭제 기능은 없습니다. 전체 메시지를 한꺼번에 보관할 수 없으며, 대화에 하나 이상을 남겨야 합니다.

## 저장과 기록

### 0.2.0 — 바로 보관하고 편하게 읽기

- 채팅 메시지의 액션 영역에 **별지에 보관** 버튼이 생깁니다. 마법봉을 열지 않고 해당 메시지만 보관합니다. 테마에 따라 메시지 액션을 펼쳐야 보일 수 있습니다.
- 저장된 `extra.display_text`가 있으면 **번역·표시문**을 먼저 보여줍니다. 기존 보관본에도 적용됩니다. 원문은 본문 선택 메뉴에서 볼 수 있습니다.
- 표시문 필드가 없는 확장은 보관할 때 화면에 렌더링된 해당 메시지 본문을 **보관 당시 화면**으로 함께 저장합니다. 화면에 로드되지 않은 메시지나 iframe 내부 번역은 캡처하지 않습니다. 별지가 새 번역 요청을 보내지는 않습니다.
- **제목·본문 수정**에서 제목과 읽기용 수정본을 저장합니다. 원문과 번역문은 보존되며, **채팅 복원 시에는 원본 메시지**를 사용합니다.
- **복사**는 현재 선택한 본문 전체를 복사합니다. 제목과 번역문, 수정본도 검색할 수 있습니다.
- 보관본이 하나면 본문을 바로 펼칩니다. 긴 본문은 계속 나눠 표시합니다.

### 저장 방식

- 보관한 메시지 객체 전체(스와이프와 확장 필드 포함)를 현재 채팅의 `chat_metadata.sideleaf_v1`에 저장하고, 활성 `chat` 배열에서 제거합니다.
- 따라서 기본 대화 화면과 이후 기본 AI 대화 기록에서 빠집니다. 단순 CSS 숨김이 아닙니다.
- 저장본은 채팅 파일과 함께 서버에 남으며, 원본 JSONL 내보내기·백업에 포함됩니다. 브라우저 로컬 저장소에만 의존하지 않습니다.
- 채팅 파일 자체를 삭제하면 그 채팅의 서랍도 함께 사라집니다. 확장을 꺼도 보관본이 활성 대화로 돌아오지는 않으며, 다시 켜면 열 수 있습니다.
- 보관 전에 이미 만들어진 요약·장기기억·벡터·프롬프트 로그에 들어간 내용을 소급해서 지우지는 않습니다. 그러한 별도 기억까지 제외하려면 해당 확장에서 관리해야 합니다.
- 파일 저장 후 서버에서 보관함 revision을 다시 읽어 확인합니다. 실패하면 성공으로 표시하지 않고 재시도와 전체 채팅 JSONL 백업을 제공합니다. 백업 후 닫으면 변경 내용은 현재 메모리에 남으며, 필요할 때 백업을 새 채팅으로 가져올 수 있습니다.
- 여러 브라우저가 같은 채팅을 동시에 편집하는 상황은 SillyTavern 자체의 충돌 처리 범위를 따릅니다.

## 성능과 호환

- 페이지당 30개, 긴 본문은 펼칠 때 20,000자 단위로 표시합니다.
- 닫혀 있을 때 메시지 전체 스캔, 타이머, MutationObserver, 스트리밍 토큰 감시는 없습니다.
- 스타일은 전용 ID 아래로 제한하고 SillyTavern 테마 색을 따릅니다.
- 기존 메시지 액션이나 마법봉 항목을 대체하지 않습니다.
- 보관함은 원문 텍스트로 표시합니다. HTML·iframe·QR 스크립트·매크로를 다시 실행하지 않습니다. 첨부 파일과 추가 데이터는 복원을 위해 보존하지만 보관함에서 실행하거나 재생하지 않습니다.
- 보관함 데이터는 채팅 메타데이터이므로 채팅 로딩·저장 시 함께 처리됩니다. 대용량 보관본의 서버 저장 비용까지 없어지는 구조는 아닙니다.
